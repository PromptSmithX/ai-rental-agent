# Prompt — triển khai Data Ingestion v1

You are a senior Python data engineer implementing **Data Ingestion v1** for AI Rental Copilot. This repo has an existing React/TypeScript frontend and a FastAPI/PostgreSQL backend. The user reports permission from the Trọ Mới administrator to crawl. Scope is **Hà Nội only**, seed URL `https://tromoi.com/tim-tro-tai-ha-noi`. Goal: capture all permitted Hanoi listing detail records and images (NO video binaries), preserving raw data and snapshot history. This phase is **not** about LangGraph, LLM, RAG or AI tools.

Read and obey `README.md` and every document in `docs/ingestion/` in order. Inspect actual backend SQLAlchemy/Alembic schema, existing frontend RoomView, and source permissions before coding; **never assume the documentation matches the current repo**. The prior `docs/contracts/06-DATA-CONTRACT.md` remains the frontend contract. New ingestion requirements supersede frontend-only development restrictions *for this module only*.

**Step 0 — preflight.** Report codebase findings and a migration plan. Confirm written authorized scope, collection rate, whether images may be downloaded, stored and shown publicly, and any terms/robots restrictions. If rights details remain unknown, default to metadata-only image collection and do not bulk crawl until permitted; do not bypass blocks, CAPTCHA or authentication. Exclude personal contact fields by default.

**Step 1 — schema & migrations.** Implement Pydantic v2 typed raw payload schema with `extra='allow'` for source extras, immutable snapshot entity, SQLAlchemy tables for `ingestion_runs`, `raw_listings`, `raw_listing_snapshots`, `raw_listing_images`, `ingestion_errors` according to proposed DDL. Adapt naming to existing conventions, use Alembic; never destructively alter production/canonical Rooms tables. Guarantee `(source, normalized_url)` identity and snapshot uniqueness on stable content hash. Include policy flags for image usage.

**Step 2 — local fixture parser.** Build a `TromoiSourceAdapter` to parse fixture HTML/structured data with independently extracted summary price, description price, new/old addresses, tags, surroundings, tenant labels, dates, ordered image references, and video *metadata only*. Preserve full original description and conflicting values. Validate selectors on obtained permitted HTML instead of inventing CSS selectors or undocumented APIs. Unit-test against a fixture constructed from screenshots plus any authorized saved pages.

**Step 3 — collector.** Add scoped URL discovery, bounded rate and concurrency, Retry-After/backoff, host whitelist, redirect/SSRF protection, stop on denial, deterministic URL normalization, resumable per-URL state, run records, per-stage errors, dry run and CLI flags `--scope hanoi --max-listings N --resume --no-images --profile-only`. Verify detail location belongs to Hà Nội. Never download video assets. Implement image downloader ONLY when separately authorized; check image type, byte/pixel limits, SHA256, duplicate URLs and atomic writes; save metadata even when download disabled.

**Step 4 — reports.** Generate JSON/CSV reports of field completeness, price conflicts, parser warnings, raw metadata coverage, invalid URLs, image/download/rights coverage, source geo accuracy, and dedupe candidates. Keep personally identifying information out of reports.

**Step 5 — tests & rollout.** Add tests for 18 edge cases in `06-VALIDATION-TESTING.md`, db idempotency, migrations, canary collection and crash/resume. Run formatter/linter, typecheck if configured, `pytest`, Alembic upgrades (isolated test DB). First operate 20–50 authorized varied Hanoi details as canary, review profiling and schema compatibility, then support bounded full-Hanoi collection under permission/rate budgets. Log counts measured from actual execution, not invented counts.

**Deliverables:** application code, Alembic migrations, sample env/config without secrets, CLI commands and README, tests, real profiling artifacts if run, a schema compatibility/migration decision report. Do not modify frontend UI or implement AI. Before implementation, provide plan, file tree and permission ambiguities; then work phase-by-phase and summarize test results with actual logs.
